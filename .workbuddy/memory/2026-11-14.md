## 真机验证发现并修复的 8 个问题（按发现顺序）

1. **jwt.refresh_ttl "7d" bug**：Go time.Duration 不支持 "d" 单位，viper 解码失败导致控制面启动 panic。修复：默认值改 168h（config.go + config.example.yaml）。commit 513caaa
2. **GHCR 镜像默认私有**：服务器无法匿名 pull。修复：手动设 public + release.yml 加自动公开步骤（该步骤 GITHUB_TOKEN 缺 packages scope 实际 404，靠手动公开解决）。commit e0f0447
3. **1GB 内存 OOM**：5 容器跑不动，control-plane 被 OOM kill 反复重启。修复：加 2G swap（运维操作，非代码）。
4. **sing-box 内核未内置**：单机部署时 agent 无内核。修复：edge-agent 镜像构建时下载对应架构 sing-box + entrypoint 同步到数据卷。commit ae7a9e4
5. **alpine musl 无法运行 sing-box glibc 二进制**：报 "no such file or directory"。修复：运行镜像改 debian:bookworm-slim。commit ae7a9e4
6. **DNS 旧格式**：sing-box 1.14 移除 legacy DNS 格式（address 字段）。修复：DNSServer 改 type/server/server_port/path 新格式。commit cb24a6d
7. **route 缺 default_domain_resolver**：sing-box 1.14 强制要求。修复：buildRoute 默认指向第一个 DNS tag。commit b7ef272
8. **首次下发误判回滚**：apply 假设 sing-box 已运行，首次下发时 Reload 返回 ErrNotRunning 被误判失败。修复：Reload 返回 ErrNotRunning 时改冷启动 Start。commit c383700
9. **容器内 Setsid 报 EPERM**：edge-agent 是 PID 1，子进程 setsid() 返回 operation not permitted。修复：去掉 Setsid，保留 Setpgid + Pdeathsig。commit fd9927f

## 面板崩溃修复（null.reduce）

### 问题
面板打开白屏报错：`Unexpected Application Error! Cannot read properties of null (reading 'reduce')`

### 根因
后端 /traffic/nodes 和 /traffic/users 在无流量记录时返回 data:null
（service 层 `var out []NodeStat` 未初始化，GORM Scan 空结果保持 nil，
JSON 序列化成 null）。前端 dashboard/traffic 页面对 null 调 .reduce() 崩溃。

### 修复（双层，commit ba61af7，v0.2.5）
1. 后端 traffic/service.go：`var out []NodeStat` → `out := make([]NodeStat, 0)`
2. 前端 dashboard/traffic：`.then(v => setX(v ?? []))` + `(x ?? []).reduce()`

### 连带问题
1. 节点自动纳管"登录失败重试3次"：服务器跑的旧版 install.sh + 占位 token，
   手动创建节点回填真实 agent_token 解决
2. swap 丢失（重新部署导致）：重新 dd 创建 2G swap + 持久化 fstab

### 关键经验
- Go 的 nil slice 序列化成 JSON null，前端必须用 ?? [] 兜底
- 后端接口约定：空集合必须返回 [] 而非 null（前后端契约）
- 重新部署会丢 swap/fstab 手工配置，install.sh 应考虑自动加 swap

## 真机验证发现的关键 bug（ECS 38.69.243.91）

### 背景
处理全部遗留问题 + 真机验证完整流程。真机验证发现 5 个真 bug（单测全绿但真机才暴露）：

1. **grpc v1.85 拉高 go 版本**：要求 go 1.26，但 CI/Dockerfile 用 golang:1.22-alpine → CI 构建必失败。修复：钉 grpc v1.67.0 + x/text v0.17 等，go 回 1.22。
2. **install.sh json_field python3 分支 heredoc 覆盖管道**：无 jq 环境（ECS）下解析 JSON 失败，导致节点纳管/reprovision 全失败。修复：改 -c 传参 + 处理 `.data.access_token` 开头空串 + 支持 `data[0].id`。
3. **install.sh 本地源码模式 pull 旧镜像**：LOCAL_SRC 时仍 pull GHCR 旧 latest 镜像覆盖新代码。修复：本地模式直接 build 跳过 pull。purge 也不删本地源码的 docker-compose.yml。
4. **sing-box 官方二进制不含 v2ray_api**：T02 流量统计依赖 v2ray_api，官方二进制默认不编译（with_v2ray_api tag 关闭）→ 下发配置报 "v2ray api not included"。修复：edge-agent Dockerfile 自编译 sing-box（golang:1.26 + 官方默认 tags 去掉 naive/tailscale + with_v2ray_api）。
5. **configsvc 无出站时 route.final=direct 引用不存在的 outbound**：用户只创建入站时，outbounds 空但 route.final="direct" → sing-box 启动失败 "default outbound not found"。修复：Generate 里 outbounds 空时注入默认 direct。
6. **edge-agent apply 进程已死时 Reload 失败直接回滚**：sing-box 因旧配置崩溃后，supervisor rt 指向死进程，新 config_push 到达时 Reload 失败直接 rollback，不冷启动。修复：Reload 失败（ErrNotRunning 或 err!=nil）都冷启动 Start。

### 关键经验
- sing-box 编译在 1GB 内存机器极慢（20+ 分钟），且 v1.14.4 引入 with_ccm/with_ocm（AI 功能）依赖 openai-go 等大库。生产应在 CI/强机构建镜像，不该在小机编译。
- sing-box 版本要求：v1.14.4 需 go 1.25.5+。
- Docker 数据卷幂等复制导致升级时旧 sing-box 内核不更新（entrypoint 仅当卷内无才复制）。
- 注释不会进 Go 二进制（-s -w），验证二进制是否含新代码应搜字符串常量而非注释。
