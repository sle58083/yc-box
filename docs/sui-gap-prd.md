# S-UI 功能全量对标 PRD（yc-box 对齐）

## 一、项目信息

| 项 | 内容 |
|---|---|
| 文档语言 | 简体中文 |
| 对标基准 | S-UI（Teminuosi/s-ui，sing-box 单体管理面板） |
| 我方项目 | yc-box（sle58083/yc-box，多机分布式：control-plane Go + edge-agent Go + web React，Docker Compose + SQLite） |
| 技术栈 | Go + React，不改架构栈 |
| 原始需求复述 | 以 S-UI 全部功能为基准，盘点 yc-box 差距，输出差距清单与可交付需求池，供架构师任务分解 |

> 说明：本文档所有「yc-box 现状」均来自主理人已核实的代码事实，不臆测未核实能力；标注 `*` 的项为现状快照未覆盖、需架构师核实后再定级。

## 二、产品目标

以 S-UI 为功能基准补齐 yc-box 在「订阅、流量统计、限速配额、证书管理、安全加固、部署健壮性」六维度的差距，达到 **S-UI 能做的 yc-box 都能做、S-UI 做不到的（分布式多机纳管、RBAC 安全）yc-box 已更强** 的对齐目标。

## 四、需求池

### P0（必须，缺失即核心能力不完整）

| ID | 需求 | 差距现状 | 交付范围（边界清晰） | 验收标准 |
|---|---|---|---|---|
| R1 | 实时流量统计（stats API 接入） | stats API 采集为 stub，仅心跳摘要 | edge-agent 调 sing-box stats API 采集各 inbound/outbound 计数器，经 RPC 上报 control-plane 落库，替换/补充心跳摘要；确定采集频率与 SQLite 表结构 | 面板可查单用户/单节点近实时上下行，误差 < 采集周期 |
| R2 | 单连接限速 + 配额到期执行 | 无 speed limit 字段；QuotaBytes/ExpireAt 执行语义未明确 | proxy_user 增加 speed limit 字段并下发数据面；明确超额/到期后「断流 or 告警」并在 edge-agent 执行 | 超限速连接被限速、超额/到期用户被拦截，行为可观测 |
| R3 | 证书管理（ACME/Let's Encrypt 自动签发 + 手动导入） | 完全缺失 | cert 模型 + ACME 签发/续期 + 手动证书导入 + 与节点/TLS 绑定下发 | TLS 类节点可自动签发并自动续期，无需人工维护 |

### P1（应当，高价值 / 有过渡方案或安全加固）

| ID | 需求 | 差距现状 | 交付范围 | 验收标准 |
|---|---|---|---|---|
| R4 | Clash 完整 YAML 订阅 | ContentClash 仅 base64(URI 列表)，Clash 客户端不可用 | 生成标准 Clash/Mihomo YAML（proxies + proxy-groups + rules，覆盖 ws/tls/reality/udp/flow 等字段与命名规则） | Clash Verge/Mihomo 直接导入即用，多节点分组正确 |
| R5 | 面板路径随机化 | web 走 `/` 根路径 | 支持随机隐藏路径配置，兼容反向代理/子路径部署，给出既有实例迁移方案 | 未知路径 404，已知路径可访问，升级不丢失配置 |
| R6 | install.sh 自动加 swap | 未做，1GB 小内存机 OOM 根因 | 部署时检测内存，低于阈值自动创建/启用 swap，purge 时清理 | 1GB 机器部署不再因 OOM 失败 |

### P2（可选 / 增强）

| ID | 需求 | 差距现状 | 说明 |
|---|---|---|---|
| R7 | 防火墙自动开放（ufw/firewalld） | 现状未体现 `*` | 部署时自动放行面板/节点端口 |
| R8 | 旧版本迁移 | 现状未体现 `*` | 升级时平滑迁移旧配置/数据 |
| R9 | 交互式部署模式 | 仅全自动，交互式未明确 | 保留全自动为默认，交互式作为可选 |
| R10 | 轻量单机 all-in-one 模式 | 现为多机分布式 | 架构可选，非强制（S-UI 单机能力，yc-box 已有多机更强） |

**优先级理由**：R1/R2/R3 定为 P0——分别对应「面板核心数据能力是 stub」「资源管控字段缺失」「证书完全缺失且 TLS 协议依赖」，属缺失即核心不完整或安全能力缺位。R4 虽用户价值高（解锁 Clash/Mihomo 客户端），但已有 base64 URI 列表可作 sing-box 过渡，故 P1。R5 为安全加固、已有 RBAC+随机凭据兜底；R6 为稳定性修复，均 P1。R7-R10 为增强或待核实项，P2。

## 四·补：用户拍板决策（2026-11-14）

| 需求 | 原定 | 用户决策 | 影响 |
|---|---|---|---|
| R2 限速/配额执行 | 单连接限速 + 配额到期断流 | **彻底 descope**，不做任何限速（优先最大带宽），QuotaBytes/ExpireAt 字段保留但不做执行 | 移除 speed limit 字段、EnforceQuotas、quotaLoop、断流链路 |
| R3 证书管理 | ACME/Let's Encrypt 自动签发 | **改为自签证书 + 手动导入**（无域名场景，ACME 不适用） | 移除 certmagic，改用 crypto/x509 自签；保留 file_push 跨机下发 |

## 五、用户故事（P0 各一条）

- **R1**：作为面板管理员，我想要看到接近实时的每个用户/节点上下行流量，以便及时发现异常流量并做出限速或封禁决策。
- **R2**：作为服务运营者，我想要为每个用户设置单连接速率上限与到期时间，并在超额/到期后自动限速或断流，以便控制带宽成本并支撑订阅计费。
- **R3**：作为部署者，我想要面板通过 ACME/Let's Encrypt 自动签发并续期 TLS 证书（或手动导入），以便 TLS/Reality 类节点无需手工维护证书即可安全上线。

## 六、待确认问题（需向用户/架构师澄清）

1. **限速粒度**：speed limit 是 per-user 还是 per-connection（或两者）？sing-box 数据面原生支持 per-user 限速，还是需按 inbound 配置？
2. **配额到期执行语义**：到期/超额后是「断流」还是「仅标记 + 告警」？是否需 edge-agent 数据面实时拦截？
3. **证书管理范围**：是否只覆盖 TLS（VMess/VLESS over TLS）？Reality 用偷取证书（无需 CA）、Hysteria2/TUIC 用自签，ACME 是否仅服务 TLS 类？是否需多域名/SNI？
4. **面板路径随机化**：是否确有必要？既有实例如何迁移（现有用户书签/入口）？是否与随机凭据联动？
5. **Clash YAML 细节**：是否支持 Mihomo 特定字段（reality/ws/udp/flow）？分组与节点命名规则由谁定？
6. **stats API 通道**：edge-agent 是否已具备调 sing-box stats API 的通道，还是需新增 RPC？采集频率与 SQLite 表结构方案？
7. **R7/R8 现状核实**：yc-box 是否已有防火墙开放、旧版本迁移能力（现状快照未覆盖），需架构师核实后再定级。
8. **R9 交互式部署**：是否保留全自动为默认、交互式为可选？
